## 📖 О проекте

Гильдия собирается на контент, продаёт добытый лут и распределяет серебро
между участниками. Офицер вводит сумму и список игроков - бот начисляет доли,
сохраняет историю и отправляет личные уведомления.

SQLite хранит балансы и операции. Google Sheets служит зеркалом
и позволяет добавлять игроков и вносить изменения.

> Бот ведёт учёт выплат. Перевод серебра в самой игре выполняется отдельно.

## ✨ Возможности

### 💰 Экономика

- `/split` - распределение лута: 20 полей с автодополнением ников
  и текстовое поле для большого списка.
- Суммы в форматах `24м`, `24m` и `24000000`.
- `/pay` - выплата накопленного баланса одному игроку.
- `/payall` - массовая выплата с подтверждением автора команды
  и таймаутом 60 секунд.
- `/payouts` - положительные балансы по убыванию суммы.
- `/set` - ручная правка баланса с записью старого и нового значения.
- Личные уведомления о начислениях и выплатах, если их доставка разрешена.

### 📜 История и статистика

- Журнал операций: автор, время, тип и подробности.
- `/undo` - отмена сплита, выплаты, массовой выплаты или ручной правки.
- `/last` - последние операции.
- `/history` - история и суммарная статистика игрока.
- `/week` - личная сводка за календарную неделю и сравнение с прошлой.
- Отменённые операции сохраняются с отметкой об отмене.

Изменения, импортированные из таблицы (`sheet_*`),
не откатываются командой `/undo`.

### 🔄 Синхронизация

- Автоматически каждые 30 минут, фоном после изменений и вручную через `/sync`.
- Один запрос `get_all` для чтения.
- Один запрос `sync` для отправки всех игроков, логов и heartbeat.
- Без чанков по 25 игроков и отдельного `finalize_players`.
- Сортировка массива в памяти Apps Script.
- Запись только в колонки **B** и **D** основного листа.
- Колонка **C** не изменяется и может оставаться объединённой.
- Защита от пустой отправки и валидация входных данных.
- До трёх попыток при временных сбоях HTTP-обмена.
- Защита новых логов от дублирования при повторной отправке.

### 📡 Мониторинг

- `/check` - диагностика семи компонентов.
- Проверка последнего результата синка, его давности и очереди логов.
- Лист `Status` - состояние, время контакта и число игроков.
- Уведомления ответственным при серии быстрых перезапусков.
- Ежедневная копия балансов на скрытый лист `Backup`.
- Краткие сообщения в журнале без отладочных дампов HTML.

## 🏗 Архитектура

| Компонент | Назначение |
| --- | --- |
| discord.py | Слэш-команды, права, кнопки и уведомления |
| SQLite | Балансы, операции и метаданные синка |
| asyncio + aiohttp | Фоновые задачи и HTTP-запросы |
| Google Apps Script | Валидация, чтение и запись таблицы |
| Google Sheets | Зеркало балансов, журнал, статус и бэкап |
| systemd | Запуск и перезапуск процесса |

Команды работают с локальной SQLite. После изменений бот запускает
синхронизацию в фоне.

### Алгоритм синхронизации

1. Бот получает игроков из таблицы.
2. Новые игроки добавляются в SQLite.
3. Правка баланса из таблицы принимается, если локальный баланс
   равен `last_pushed` - последнему подтверждённому отправленному значению.
4. Если на листе не менее пяти ников, отсутствующие игроки удаляются из базы.
5. Игроки, неотправленные логи и heartbeat передаются одним запросом.
6. После успешного ответа подтверждаются только отправленные данные.

Изменения, внесённые командами во время запроса, остаются для следующего синка.

> Порог удаления не защищает от всех ошибок редактирования таблицы.
> Один запрос Apps Script не является транзакцией Google Sheets:
> после частичного сбоя может потребоваться повторная синхронизация.

## 🗄 Данные

### SQLite

| Таблица | Содержимое |
| --- | --- |
| `players` | Ник, баланс, `last_pushed` |
| `operations` | ID, дата, автор, тип, подробности и признак отправки |
| `sync_meta` | Постоянный идентификатор источника для ключей логов |

### Google Sheets

| Лист | Размещение |
| --- | --- |
| `CoE LootSplit` | Ники - **B6:B**, балансы - **D6:D** |
| `Logs` | С 6-й строки: дата - **B**, автор - **D**, тип - **F**, подробности - **H** |
| `Logs`, колонка **J** | Скрытые ключи операций; заголовок - **J5** |
| `Status` | Состояние - **D4**, время - **D6**, число игроков - **D8** |
| `Backup` | Дата - **B1**, ники и балансы - **A3:B** |

В колонках **B** и **D** основного листа внутри данных не должно быть
объединённых ячеек.

Колонка **J** листа `Logs` должна быть свободна при первом запуске.
Если она занята, измените `LOG_KEY_COL` в Apps Script на свободную колонку.
Не удаляйте служебные ключи операций.

## ⚙️ Установка

### Зависимости

```bash
git clone https://github.com/Koowia/lootsplit-bot.git
cd lootsplit-bot

python3.12 -m venv .venv
.venv/bin/python -m pip install 'discord.py>=2,<3' aiohttp
```

### Конфигурация

Создайте `.env`:

```dotenv
DISCORD_TOKEN=your_discord_bot_token
GOOGLE_SCRIPT_URL=https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
GUILD_NAME="Your Guild"
OFFICER_ROLE_IDS=123456789012345678
ALERT_OWNER_IDS=111111111111111111,222222222222222222
```

Укажите свои ID и пути. Несколько ID перечисляются через запятую.

```bash
chmod 600 .env
```

Бот читает переменные окружения и не загружает `.env` самостоятельно.
Для systemd используйте `EnvironmentFile`.

Ручной запуск в Bash с собственным доверенным `.env`:

```bash
set -a
source .env
set +a
.venv/bin/python bot.py
```

### Discord и Apps Script

1. Создайте Discord-приложение и добавьте бота на сервер.
2. Включите используемые кодом Server Members Intent и Message Content Intent.
3. Выдайте необходимые права на просмотр каналов, отправку сообщений,
   embed-сообщения и чтение истории.
4. Создайте листы `CoE LootSplit`, `Logs` и `Status`.
5. Вставьте `Code.gs` в привязанный к таблице проект Apps Script.
6. Разверните веб-приложение с выполнением от владельца и доступом
   для запросов бота без интерактивного входа.
7. Укажите опубликованный URL `/exec` в `GOOGLE_SCRIPT_URL`.

Python и Apps Script должны использовать совместимый **протокол 2**.
После изменения Apps Script обновите опубликованную версию развёртывания.

## 🚀 Деплой

Порядок обновления со старой версии:

1. Остановить бот и сделать резервную копию кода и SQLite.
2. Опубликовать новую версию существующего развёртывания Apps Script.
3. Заменить `bot.py`.
4. Проверить синтаксис и запустить сервис.
5. Проверить журнал, `/sync`, `/check` и содержимое таблицы.

```bash
python3 -m py_compile bot.py
sudo systemctl restart lootsplit
sudo journalctl -u lootsplit -n 50 -f --no-pager
```

Ожидаемое сообщение после успешного цикла:

```text
✅ Синк завершён: N игроков, M логов
```

Проверка синтаксиса не заменяет просмотр журнала после запуска.

## 🧪 Тесты

```bash
.venv/bin/python -m pip install pytest

# Базовые тесты проекта
.venv/bin/python -m pytest -v test_bot.py

# Тесты обновлённой синхронизации
.venv/bin/python -m pytest -v test_sync.py

# Сценарии Apps Script с имитацией Sheets
node test_apps_script.cjs
```

Для выпуска single-sync локально прошли **16 новых тестов Python**
и **10 сценариев Apps Script**.

Проверяются отправка одним запросом, подтверждение снимка,
изменения во время отправки, обработка ошибок, совместимость протокола,
ретраи, редиректы и повторная отправка логов.

Тесты не подключаются к реальным Discord и Google.
После деплоя требуется проверка полного цикла.

Node.js нужен для тестов Apps Script, но не для работы Python-бота.

## 🛡️ Доступ и резервные копии

- Офицерские команды проверяют роли пользователя.
- Проверка роли ограничивает выполнение, но сама по себе не скрывает команды.
- Видимость команд и разрешённые каналы настраиваются в интеграциях Discord.
- Ошибки команд, отправленные через обработчик ошибок, видит только их автор.
- `.env`, SQLite, файлы `-wal`/`-shm`, состояние запуска и бэкапы не должны попадать в Git.
- Лист `Backup` содержит балансы, но не полную историю операций.
- Для полного восстановления нужна отдельная резервная копия SQLite.
